# Internationalization (i18n)

## Architecture

The i18n system is built on **use-intl** (`use-intl/core`) with a custom reactive `Translator` class at `$lib/core/i18n/index.svelte.ts`.

- **Languages**: Uzbek (`uz`), Russian (`ru`), English (`en`) — defined in `$lib/constants.ts`.
- **Locale files**: `$lib/locales/en.json`, `$lib/locales/ru.json`, `$lib/locales/uz.json`.
- **Persistence**: The active locale is stored in a cookie (`locale`) and survives page reloads.
- **Fallback**: Uzbek (`uz`) is the default language.
- **Global singleton**: `$lib/index.ts` exports `i18n` — a single `Translator` instance.

## Usage in Components

Always destructure `t` from `i18n` using `$derived` so it stays reactive when the user changes language:

```svelte
<script lang="ts">
  import { i18n } from "$lib";
  const { t } = $derived(i18n);
</script>

<h1>{t("page-title")}</h1><p>{t("welcome-to", { site: "1LC" })}</p>
```

## The `t()` Function

### Simple keys

```svelte
{t("save")}
<!-- → "Save" / "Сохранить" / "Saqlash" -->
{t("cancel")}
<!-- → "Cancel" / "Отмена" / "Bekor qilish" -->
```

### Interpolation (ICU Message Syntax)

Pass named parameters as the second argument:

```svelte
{t("welcome-to", { site: "1LC" })}
<!-- en.json: "welcome-to": "Welcome to {site}!" -->
<!-- Result: "Welcome to 1LC!" -->
```

### Pluralization

```svelte
{t("input.min", { name: "Password", min: 8 })}
<!-- en.json: "input.min": "{name} must not be less than {min, plural, =1 {one character} other {# characters}}" -->
```

### Select (enum-like)

```svelte
{t("theme", { theme: "dark" })}
<!-- en.json: "theme": "{theme, select, light {Light} dark {Dark} other {System}}" -->
```

### Nested keys

Locale files support nested objects. Access with dot-separated paths:

```svelte
{t("landing.heading")}
{t("input.required", { name: t("email") })}
```

## Adding New Translation Keys

When you add **any** new user-facing string, you **MUST** add the key to **all three** locale files simultaneously:

1. `$lib/locales/en.json` — English
2. `$lib/locales/ru.json` — Russian translation
3. `$lib/locales/uz.json` — Uzbek translation

This is enforced by TypeScript — the type system infers allowed keys from the JSON files. Missing keys will cause a TS error:

```
Argument of type '"my-new-key"' is not assignable to parameter of type 'NamespacedMessageKeys<...>'
```

### Key naming conventions

- Use **kebab-case**: `"add-student"`, `"no-results"`, `"finance-overview"`
- Use **nested objects** for page-specific or grouped strings: `"landing.heading"`, `"input.required"`
- Avoid generic single-word keys that might conflict — be descriptive: `"no-payments-for-this-period"` not `"no-data"`

## Accessing `format` (date/number formatting)

The `Translator` also exposes a `format` property powered by `use-intl`'s `createFormatter`:

```svelte
<script lang="ts">
  import { i18n } from "$lib";
  const { format } = $derived(i18n);
</script>

{format.dateTime(new Date(), { month: "long", day: "numeric" })}
{format.number(1500, { style: "decimal" })}
```

> **Note**: For most date formatting needs, use the `getFormat()` hook from `$lib/hooks/format.svelte.ts` instead — it adds locale-aware presets and relative time support. See `hooks.md`.

## Accessing `locale` (current language code)

```svelte
<script lang="ts">
  import { i18n } from "$lib";

  // Read:
  const currentLocale = i18n.locale; // "uz" | "ru" | "en"

  // Write (changes language immediately):
  i18n.locale = "ru";
</script>
```

## Server-Side Hydration

In `+layout.server.ts`, call `i18n.init(cookies)` to sync the locale from the request cookie and prevent hydration mismatches:

```ts
export const load = async ({ cookies }) => {
  i18n.init(cookies.getAll());
};
```
